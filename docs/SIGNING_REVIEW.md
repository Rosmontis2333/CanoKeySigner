# 签名有效期与结果交付检查

2026-11-09。本次检查覆盖已实现交易和消息的一次性批准、OpenPGP 设备执行、认证退出、附签，以及 EVM/Solana RPC 上下文组合。设备和时钟使用合成测试数据，实际设备长时间等待与跨系统行为仍需验收。

| 检查项 | 原行为与影响 | 修复后行为 |
| --- | --- | --- |
| 五分钟批准在设备操作中到期 | 批准主要在消费时检查。单次签名可能在过期后返回，Bitcoin 最后一个输入结束后缺少截止检查 | 在发现前、发送 PIN 前、发送签名命令前及认证退出后检查批准。Bitcoin 每个输入和最终组装前同样检查 |
| RPC 在设备发现或 PIN 验证期间到期 | 附签会拦截过期结果，但可能已发出后续 PIN 或签名命令 | 每个设备检查点同时核对对应审查对象的 RPC 截止时间，在下一条敏感命令前停止 |
| 组合已有 RPC 审查 | 再包装可设定比旧上下文更晚的截止时间，并可为旧对象建立新期限 | 组合取较早截止时间，已过期对象拒绝再包装，主动重新读取会建立新的审查 |

验证使用正常 executeReviewedTransaction 入口。时间推进到批准的精确截止点，分别覆盖设备发现、PIN、签名/触摸和认证退出。Bitcoin 的双输入案例另外覆盖最后一个签名及最后一次认证退出后的过期。各条链也验证截止前一毫秒仍可完成有效签名。

新增 14 项回归包含三链交易、EVM personal_sign、Solana 离链消息、较短 RPC 期限及上下文组合。检查过期结果无法交付、尚未发送的 PIN/签名命令保持未发送、PIN 缓冲清零，以及已经开始验证时继续退出两个 PW1 用途。初次新增回归在旧实现出现 7 项失败，修复后通过。[回归测试](../test/signing-deadlines.test.ts)

设备路径在抛出过期错误时保留 authenticationCleared，避免丢失认证退出结果。取消或错误 PIN 仍沿用已有清理与单次尝试路径，失败任务不会重试。诊断审批的一次性消费保留独立逻辑，业务签名的重复有效性检查绑定已批准的审查对象。[设备执行](../src/device/openpgp.ts) · [单次批准](../src/signing/approval.ts)

广播使用独立批准。准备时核对签名交易与原审查，提交前核对网络、查询已有状态并读取新执行上下文，写入前再次检查任务期限。网络和交易标识在当前页面内共同限制为一次写入尝试，响应不确定时保留标识供查询。本次修改集中在设备执行与 RPC 截止时间，真实节点提交和链上执行仍属后续验收。[广播实现](../src/network/broadcast.ts) · [提交协议](BROADCAST_PROTOCOL.md)

设备选择阶段另复现了取消后页面仍保持“正在读取设备账户”的问题。等待原生选择结果现已响应 AbortSignal，取消立即结束页面任务，迟到的设备或拒绝结果会被消费并忽略，选择完成后移除事件监听。5 项回归覆盖立即取消、已取消信号、迟到成功/失败、后续新选择和正常错误。浏览器确认取消后连接与重新读取按钮恢复可用，取消按钮禁用，状态显示“设备选择已取消”。原生窗口由操作者手动关闭。[设备选择等待](../src/device/webusb.ts) · [回归测试](../test/webusb.test.ts) · [界面记录](screenshots/device-selection-cancel-2026-11-09.png)
